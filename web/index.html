How this dashboard works

Left menu (black bar)
Dashboard

Calls health and stats. Shows KPI cards, directive usage donut, average saving per plan type and the 10-sample cost comparison.

Scenario list

Calls scenarios. Filter by source or search by id/label. Click a row: calls scenario and opens notes, rules chart and plans.

Import a case

Paste JSON and press Import: import_case inserts everything in one transaction. A broken rule rolls it all back.

Light / Dark

Switches the theme. It is saved in your browser.

Collapse menu

Switches the bar between icons only and icons + labels.

Top bar
Search (Ctrl K)

Type an id or label and press Enter. It opens the Scenario list with that filter applied.

Refresh

Reloads the data of the page you are on.

API badge

Green = API and DB reachable (shows DB version). Red = API problem.

Dots on a card

Show / hide the SQL view or table that card reads from.

Inside a scenario
Plan buttons

Each plan loads plan + validate: totals, hourly chart, table and rule check.

+ Create baseline plan

Calls baseline: makes a no-battery plan. If a trigger blocks it, the reason is shown.

Delete this case

Calls delete_scenario. Only visible for cases with source = user.

RDBMS Architecture Highlights

Relational Schema: 10 Normalized Tables adhering strictly to Boyce-Codd Normal Form (BCNF).

Procedural Integrity: 6 BEFORE/AFTER Triggers with SIGNAL SQLSTATE '45000' enforcing energy balance and battery state continuity.

Analytical Queries: 11 Views, 26 Advanced SQL Queries (Window functions, CTEs, Running totals), and 18 Automated Unit Tests.

Target Stack: MySQL / MariaDB on XAMPP with PHP PDO RESTful API.
